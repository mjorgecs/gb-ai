# Why the shift?

- It is more simple to build: it requires less explanation, the interaction with the user is relatively easy since the agent only needs to interpret the requirements of the user's application and match them with the information stored in the tables. 
	- Advantages and disadvantages: one advantage and one disadvantage.
- Work directly with the platform: the results (the JSON objects generated by the agent) can be easily manipulated by putting them into the main JSON object which modifies the application's structure. 
	- Advantages and disadvantages: one advantage and one disadvantage.
- Design: probably the less affected characteristic of the app. Since the agent will only select the sections and them templates, the idea is to have default designs (as it already happen new a new section is add in the back office), by doing this, we will keep the design choices on the user side while we will deal with the selections of the services that the user needs to build the app.
	- Advantages and disadvantages: one advantage and one disadvantage.
- Less token consumption: with a fixed set of information, the reasoning process can be more fast the the results more accurate while consuming less tokens since the output is more shorter.
